Навчальний проєкт з дисципліни «Геймдизайн та програмування ігрових застосунків». РФКІТ, група КН-3/1, 2026/27.

## Щоденник розробника

### 20.09.2026 — Юніт 1: персонаж і рух
**Що зроблено:**
Я створила нову сцену MainScene, додала на неї персонажа та створила скрипт PlayerController. Налаштувала нову Input System через MoveAction: прив'язала стрілочки та клавіші WASD для керування. Створила об'єкт Grid та Tilemap підлоги, виставила Pixels Per Unit = 64 та Order in Layer = -10. Також виконала два пункти з домашнього завдання: додала прискорення швидкості на клавішу Left Shift (спринт) та обмежила рух персонажа по осях X і Y від -10 до 10 одиниць за допомогою Mathf.Clamp.

**Що не вийшло або забрало найбільше часу:**
Найбільше часу зайняв раптовий краш Unity під час роботи з Tile Palette. Програма закрилася, через що зі сцени видалилися об'єкти Grid та Tilemap, а також скинулися налаштування клавіш в інспекторі. Довелося створювати підлогу наново. Крім того, виникали помилки компіляції коду через те, що інші готові скрипти проєкту вимагали наявності змінних здоров'я та функцій ChangeHealth, PlaySound і OnTalkedToNPC у моєму скрипті. Я додала їх у код як порожні методи-заглушки, після чого помилки зникли.

**Що зрозумів про Update і Time.deltaTime:**
Я зрозуміла, що метод Update викликається кожен кадр. Без використання Time.deltaTime швидкість руху персонажа залежала б від FPS комп'ютера (на потужному ПК він би рухався занадто швидко, на повільному — занадто повільно). Множення на Time.deltaTime дозволяє згладити рух і зробити швидкість однаковою (3 одиниці за секунду) незалежно від частоти кадрів.

**Що робитиму далі:**
У наступному юніті я планую налаштувати 2D фізику. Потрібно додати колайдери на дерева, будинки та персонажа, щоб він не проходив крізь об'єкти на сцені, а врізався в них.


### 26.09.2026 — Юніт 2: оточення і фізика
**Що зроблено:**
Я створила новий фізичний шар Water_Tilemap для води з компонентами Tilemap Collider 2D та Composite Collider 2D. Налаштувала сортування графіки за віссю Y (Custom Axis: Y=1) у файлі Renderer 2D, а також змінила точку Sprite Sort Point на Pivot у робота, щоб він правильно обходив дерева. Додала компоненти Rigidbody 2D та Box Collider 2D на робота, а також Box Collider 2D на фундамент будинку. Логіку руху повністю перенесла на метод rigidbody2d.MovePosition у FixedUpdate. Також виконала два пункти з розділу «More things to try»: винесла швидкість в інспектор (змінна speed) та розділила карту на шари підлоги й перешкод.

**Що не вийшло або забрало найбільше часу:**
Найбільше часу зайняло налаштування сортування будинку та усунення візуального багу, коли робот ходив по даху. Довелося відкривати Sprite Editor і вручну переносити синю точку Pivot у самий низ фундаменту будинку, щоб гра правильно розуміла глибину. Також виникали складнощі через ліміти веб-інтерфейсу GitHub на завантаження великої кількості файлів папки Assets, але проблему вирішила завантаженням лише змінених файлів сцени та коду.

**Що зрозуміла про FixedUpdate і колайдери:**
Я зрозуміла, що звичайний Update викликається кожен кадр і залежить від FPS комп'ютера, через що робот раніше тремтів біля стін, коли фізичний рушій намагався виштовхнути його назад. FixedUpdate працює синхронно з фізичним движком чітко 50 разів на секунду. Метод MovePosition плавно переміщує Rigidbody 2D з урахуванням колізій заздалегідь, що повністю прибирає тремтіння (jittering). Також зрозуміла, що для підлоги (трави) обов'язково потрібен Collider Type = None, інакше робот просто застрягне на місці і не зможе зробити ні кроку.

**Що в рівні вийшло не так, як у фізичному паспорті з лекції 4:**
У теоретичному фізичному паспорті з лекції об'єкти мають повноцінну масу, гравітацію та взаємодіють усією своєю площею. В Unity 2D Top-Down ми змушені штучно вимикати гравітацію (Gravity Scale = 0) та блокувати обертання (Freeze Rotation Z), інакше робот просто падав би вниз екрана або безкінечно крутився при зіткненнях. Також колайдери робота та будинку довелося штучно зменшити лише до їхньої нижньої частини (до коліс та фундаменту), хоча у фізичному паспорті вони мали б охоплювати весь об'єм. Це художнє допущення рушія для створення ілюзії глибини простору в 2D.
